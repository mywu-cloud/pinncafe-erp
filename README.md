# ☕ 咖啡烘豆進銷存系統（Coffee Roastery ERP）

專為小型咖啡烘豆坊設計的進銷存 + 帳務系統，涵蓋「生豆進貨 → 烘焙生產 → 熟豆包裝 → 銷貨收款 → 銀行對帳」完整流程，所有單據皆支援日期區間查詢。

> 詳細資料表欄位、關聯與業務規則請見 [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 一、核心功能

| 模組 | 功能 |
|---|---|
| 主檔管理 | 供應商、客戶、客戶喜好、生豆品項、產品、配方（BOM）、包材、銀行帳戶 |
| 交易 | 進貨、銷貨、退貨／折讓、訂閱訂單、應收／應付、發票 |
| 庫存與生產 | 生豆庫存（批號 Lot）、烘焙批次、熟豆庫存、包材庫存、盤點調整 |
| 財務 | 銀行入帳／出帳、費用支出、銀行對帳、成本計算 |
| 報表查詢 | 日期區間查詢進貨／銷貨／烘焙／收支、客戶購買紀錄、庫存異動、毛利分析 |
| 系統 | 使用者權限、操作日誌、Excel 匯出、網銀 CSV 匯入 |

## 二、主要資料流程

```
供應商 → 進貨單 → 生豆庫存(Lot) → 烘焙批次(失重) → 熟豆庫存
                                                    ↓ + 包材
客戶 ← 銷貨單 ← 產品(含配方) ←─────────────────── 包裝
  ↓
應收帳款 → 銀行入帳        進貨／費用 → 應付帳款 → 銀行出帳
```

## 四、設計原則

1. **庫存以異動紀錄計算**：每次進貨、烘焙、銷貨、退貨、盤點都寫入一筆「庫存異動」，現有庫存 = 異動加總。可回推任一時間點庫存。
2. **批號追溯**：生豆以進貨批號（Lot）管理，烘焙批次記錄投入哪些 Lot，熟豆可追溯回原始生豆與供應商。
3. **單據與帳務連結**：每筆銀行入帳／出帳皆對應到銷貨單、進貨單或費用單，方便對帳。
4. **購買紀錄不另建表**：客戶購買紀錄 = 依客戶篩選銷貨單。
5. **日期索引**：所有單據表的日期欄位建立索引，支援日期區間查詢。
6. **交易一致性**：單據存檔與庫存扣減在同一個資料庫交易內完成。

## 五、烘焙批次（簡化版）

只記錄兩件事：

1. 投入哪幾批生豆、各用多少公斤
2. 產出多少熟豆（失重率自動計算）

```
失重率 = (投入總重 − 產出熟豆) ÷ 投入總重
熟豆單位成本 = 投入生豆總成本 ÷ 產出熟豆 kg
```

失重率超出 10%–25% 時系統提醒，避免輸入錯誤。

## 八、安裝與部署

### 本機開發

```bash
npm install
npm run db:local      # 建立本機 D1 並匯入 schema.sql + seed.sql
npm run dev           # http://localhost:8788/admin/
```

本機未設定 Cloudflare Access 變數時為開發模式，操作者記為 `dev@local`。

### 部署到 Cloudflare

1. 建立 D1：`npx wrangler d1 create pinncafe-erp`，把回傳的 `database_id` 填入 `wrangler.toml`
2. 建表：`npm run db:remote:schema`（要範例資料再跑 `npm run db:remote:seed`，**會清空 Phase 1 資料表**）
3. 部署：`npm run deploy`，或在 Cloudflare Pages 連結此 GitHub repo（Build output directory 填 `web`，不需 build command）
4. 在 Zero Trust 為網站建立 Access Application，限定可登入的 email
5. 在 Pages 專案的環境變數設定 `CF_ACCESS_TEAM_DOMAIN`（`<team>.cloudflareaccess.com`）與 `CF_ACCESS_AUD`（Application 的 AUD Tag）

> ⚠️ 兩個 `CF_ACCESS_*` 變數沒設定時 API **不驗證登入**。正式環境務必設定。
