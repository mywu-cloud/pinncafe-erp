# ☕ 咖啡烘豆進銷存系統（Coffee Roastery ERP）

專為小型咖啡烘豆坊設計的進銷存 + 帳務系統，涵蓋「生豆進貨 → 烘焙生產 → 熟豆包裝 → 銷貨收款 → 銀行對帳」完整流程，所有單據皆支援日期區間查詢。

> 詳細資料表欄位、關聯與業務規則請見 [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 一、核心功能

| 模組 | 功能 |
|---|---|
| 主檔管理 | 供應商、客戶、客戶喜好、生豆品項、熟豆品項、產品、配方（BOM）、包材、銀行帳戶 |
| 交易 | 進貨、銷貨、退貨／折讓、訂閱訂單、應收／應付、發票 |
| 庫存與生產 | 生豆庫存（批號 Lot）、烘焙批次、熟豆庫存、包材庫存、期初庫存、盤點調整 |
| 財務 | 銀行入帳／出帳、費用支出、銀行對帳、成本計算 |
| 報表查詢 | 日期區間查詢進貨／銷貨／烘焙／收支、客戶購買紀錄、庫存異動、毛利分析 |
| 系統 | 使用者權限、操作日誌、Excel 匯出、網銀 CSV 匯入 |

## 二、主要資料流程

```
供應商 → 進貨單 → 生豆庫存(Lot) → 烘焙批次(失重) → 熟豆庫存
                                                    ↓ + 包材
客戶 ← 銷貨單 ← 產品(含配方) ←─────────────────── 包裝
  ↓
應收帳款 → 銀行入帳        進貨／費用 → 應付帳款 → 銀行出帳
```

## 四、設計原則

1. **庫存以異動紀錄計算**：每次進貨、烘焙、銷貨、退貨、盤點都寫入一筆「庫存異動」，現有庫存 = 異動加總。可回推任一時間點庫存。
2. **批號追溯**：生豆以進貨批號（Lot）管理，烘焙批次記錄投入哪些 Lot，熟豆可追溯回原始生豆與供應商。
3. **單據與帳務連結**：每筆銀行入帳／出帳皆對應到銷貨單、進貨單或費用單，方便對帳。
4. **購買紀錄不另建表**：客戶購買紀錄 = 依客戶篩選銷貨單。
5. **日期索引**：所有單據表的日期欄位建立索引，支援日期區間查詢。
6. **交易一致性**：單據存檔與庫存扣減在同一個資料庫交易內完成。

## 五、烘焙批次（簡化版）

只記錄兩件事：

1. 投入哪幾批生豆、各用多少公斤
2. 產出多少熟豆（失重率自動計算）

```
失重率 = (投入總重 − 產出熟豆) ÷ 投入總重
熟豆單位成本 = 投入生豆總成本 ÷ 產出熟豆 kg
```

失重率超出 10%–25% 時系統提醒，避免輸入錯誤。

烘焙產出的是「熟豆品項」（例：招牌綜合 中深焙）。產品主檔指定每個產品用哪個熟豆品項、每包幾克，所以 250g 與 1kg 兩種包裝共用同一鍋熟豆；銷貨時依「數量 × 每包淨重」以先進先出扣熟豆庫存。

## 八、安裝與部署

### 本機開發

```bash
npm install
npm run db:local      # 建立本機 D1 並匯入 schema.sql + seed.sql
npm run dev           # http://localhost:8788/admin/
```

本機未設定 Cloudflare Access 變數時為開發模式，操作者記為 `dev@local`。`wrangler.toml` 已寫入正式環境的 Access 設定，本機開發請建立 `.dev.vars`（已在 .gitignore）把兩個變數設為空字串：

```
CF_ACCESS_AUD=""
CF_ACCESS_TEAM_DOMAIN=""
```

### 部署到 Cloudflare

1. 建立 D1：`npx wrangler d1 create pinncafe-erp`，把回傳的 `database_id` 填入 `wrangler.toml`
2. 建表：`npm run db:remote:schema`（要範例資料再跑 `npm run db:remote:seed`，**會清空所有資料表**）
3. 部署：`npm run deploy`，或在 Cloudflare Pages 連結此 GitHub repo（Build output directory 填 `web`，不需 build command）
4. 在 Zero Trust 為網站建立 Access Application，限定可登入的 email
5. 在 Pages 專案的環境變數設定 `CF_ACCESS_TEAM_DOMAIN`（`<team>.cloudflareaccess.com`）與 `CF_ACCESS_AUD`（Application 的 AUD Tag）

> ⚠️ 兩個 `CF_ACCESS_*` 變數沒設定時 API **不驗證登入**。正式環境務必設定。

### 既有資料庫升級

依序執行尚未跑過的 migration，最後再跑一次 schema：

```bash
npm run db:remote:migrate:phase2    # Phase 2：products 加 roasted_bean_id 欄位
npm run db:remote:migrate:opening   # 期初庫存：重建 inventory_movements（movement_type 新增「期初」）
npm run db:remote:schema            # 建立新表與 view，不影響既有資料
npm run db:remote:migrate:phase3    # Phase 3：依沖帳重算收付款狀態（必須在 schema 之後，可重複執行）
```

Phase 4 升級：先 `npm run db:remote:migrate:phase4`（加兩個欄位，只能跑一次），再 `npm run db:remote:schema`。

Phase 5 升級：只要 `npm run db:remote:schema`（新增五張表）。銀行代號功能：先 `npm run db:remote:migrate:bankcodes`（只能跑一次），再 `npm run db:remote:schema`。**要在部署新版之前跑**，否則登入時會找不到 users 表。

每個 migration 只能跑一次。

### 開始使用 Phase 3

1. 「主檔 → 銀行帳戶」建立帳戶：銀行帳戶、門市現金、LINE Pay、刷卡收單各一個，填期初餘額與期初日期
2. 收款、付款都在「財務 → 銀行收支」登錄，並勾選沖銷的銷貨單／進貨單／費用（現金收款也一樣）
3. 房租、瓦斯、電費等在「財務 → 費用支出」登錄，付款時再到銀行收支出帳沖銷

### 開始使用 Phase 4

1. 「主檔 → 產品配方」為每個產品設定每包用的包材（夾鏈袋、標籤、濾掛袋…），之後銷貨會自動扣包材
2. 退貨、折讓從銷貨單／進貨單上的按鈕開；客戶已付款的要再到銀行收支登錄退款
3. 訂閱在「交易 → 訂閱」建立，每天（或每次出貨前）到待出貨清單勾選產生銷貨單
4. 發票開好後在銷貨單上「登錄發票」，或到「交易 → 發票」補登未開發票的單
5. 「庫存 → 盤點／調整」做月底盤點，試喝、樣品、報廢也在這裡扣

### 開始使用 Phase 5

1. 第一次登入的人自動成為管理者（MY）。要讓員工使用：「系統 → 使用者」新增 email 與角色，**並到 Cloudflare Zero Trust → Access 把該 email 加進允許名單**
2. 費用勾選「攤入烘焙」後，「報表 → 加工成本」會算出每月每 kg 加工成本，「毛利分析」顯示扣掉加工成本後的調整後毛利
3. 「財務 → 銀行對帳」選帳戶 → 匯入網銀下載的 CSV（第一次設定欄位對應）→ 確認建議配對；對帳單有、系統沒有的直接建立收支。沒有 CSV 可「手動輸入明細」照存摺登打；「期初設定」可改帳戶期初、設定對帳起點（存摺餘額），系統會逐日檢查存摺餘額是否連續
4. 「主檔 → 銀行帳戶」依「銀行代號＋帳號」建帳戶；「主檔 → 供應商」下方填匯款帳戶（可多個、一個預設）；付款（出帳）選供應商後自動帶出收款帳戶，可一併填匯費。銀行代碼對照表在「主檔 → 銀行代碼」
5. 每個查詢頁右上角「匯出 Excel」；「系統 → 匯入／備份」可下載主檔範本批次匯入，管理者可下載全部資料備份

### Phase 2 升級後的設定


升級後請到「主檔 → 熟豆品項」建立熟豆品項，再到「產品」指定每個產品使用的熟豆品項與每包淨重。
